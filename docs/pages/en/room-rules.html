The format sets the starting rules

“Standard”, “Lecture” and “Council” are sets of starting values. You set the rules in the new class form and change them later: in the panel, from “Settings” in the class menu, or in the room itself with the lock button, “What you can do in this room”. Changes apply at once and participants don't need to rejoin; the server checks the rules on every action. The teacher can open a single cell to the group and keep the rest of the notebook locked.

The cell lock

The teacher picks one of three states: Closed — the teacher edits and runs the cell; Open to all — the group types in this cell and runs it, even if the room rules keep that for the teacher, but can't delete or move it; Council — separate answers from each student. The “Open cell” setting decides what a click on the lock does; all three states are in the menu that opens when you press and hold the lock button or right-click it.

Access to a single notebook

The room rules apply to every notebook at once, but each notebook also has an access of its own. You change it from the “Access” menu on the notebook's tab; the menu is the teacher's.

AccessWhat it means
As in the roomThe class rules, unchanged. The default for every notebook, including the room's own.
Personal — authorThe author and the teacher type, rearrange and run; everyone else watches. The author is whoever started the notebook during the class; a notebook created by the teacher has no author, and this option is unavailable for it.
Open to everyoneAny participant may type, rearrange and run, even if the room rules keep that for the teacher.
Teacher onlyOnly the teacher types and runs, even if the room is open.

Access overrides exactly three rules — “Edit cells”, “Run code” and “Change notebook structure” — and what follows from them: formatting, “Apply” on an oracle proposal, clearing your own cell's output, moving cells, “Run all” and running cells above in that notebook. Everything else stays shared by the room: files, the terminal, the shared screen, restarting the kernel, history and the oracle.

Access belongs to the notebook, not to the file: renaming the file keeps it, removing the notebook from the room clears it. When access is not “as in the room”, the tab carries a short label: “personal · name”, “mine”, “open to everyone”, “teacher only”.

The teacher grants the rights

Students' own notebooks are off by default: “Students' own notebooks” is set to “not allowed”. Otherwise, in a lecture where the teacher types and runs, any participant could grant themselves those rights with one “new notebook” click. When they are allowed, a student's notebook becomes personal at once, with whoever started it recorded as its author. A notebook the teacher started has no author and stays “as in the room”; the teacher changes any notebook's access from the “Access” menu.

“Own notebooks” and “Create and edit files” are different rules. The notebook file is written by the server — it is a projection — so a student can start their own notebook even where the class files are the teacher's. And the other way round: you may drop an .ipynb into the folder, but bringing it into the room as a notebook needs own notebooks to be allowed.

“End class” is stronger than notebook access: after the bell, personal and open notebooks are locked like everything else. “Resume class” brings them back.

Action rules and Python execution

Mind how permissions combine

If students can edit code, the teacher may unknowingly run text that someone has already changed: the source is read when the queue reaches the cell. For a strict lecture, restrict both editing and running.

Running Python has access to the room's files. Blocking uploads or edits in the interface does not stop code that is allowed to run from writing a file with open(...). Interface rules do not give each participant a separate file system.

Ending a class and moderation

“End class” leaves all actions to the teacher for now and keeps the settings and materials. “Resume class” brings back the previous rules. An empty room only means nobody is connected; it does not mean the class has ended.

To remove a participant, use “Remove from class…” in the “People” panel. Their access is blocked for 24 hours, tied to a marker in the browser; another browser or a private window can get around it. The participant's oracle questions and the answers to them are deleted, and version history won't bring them back; their Council attempts and run requests are deleted too. To lift the block early, click “Restore” in the “Removed from the class” list; deleted content is not restored.

This is a tool against disruption, not identity verification or exam proctoring.
