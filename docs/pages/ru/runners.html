Что это и когда помогает

Машина для посылок — любая машина с Docker, которая исполняет тетради посылок соревнований вашего сервера Colloq: арендованная VM на Vast, сервер вуза, рабочая станция лаборатории. Машина сама приходит к серверу по HTTPS, берёт посылку из общей очереди, исполняет тетрадь в той же одноразовой песочнице без сети, что и сервер, и отправляет результат обратно. Оценивает его сервер: материалы, очередь, скрытые ответы и метрика остаются у него. На машине работает тот же образ colloq-server, только в режиме runner — без сервера, без туннеля и без базы, один контейнер агента colloq-runner.

Машины помогают в трёх случаях:

  • Большое соревнование. Сто участников отправляют тетради в последние минуты, а мест на сервере — несколько. Машины добавляют к ним свои места; очередь остаётся одна и честная по людям, как и без машин (см. очередь).
  • Тетради на видеокарте, которые сервер не потянет. У сервера нет карт или их мало: GPU-посылки возьмут машины с картами, например VM на Vast с двумя RTX 4090.
  • Небольшой сервер. VM вуза на 8 vCPU держит занятие, а не очередь посылок. Переведите «Тетради на этом сервере» в «только метрики» — и сервер будет только оценивать ответы, которые прислали машины, а его ядра останутся занятию (см. ниже).

Для участника почти ничего не меняется: та же страница соревнования, те же пределы времени и памяти, те же исходы. Пока его посылку не может взять ни одно место — машины ещё качают образ среды или данные, или подходящей машины нет на связи, — вместо места в очереди он видит «готовится», а пока сервер считает метрику — «оценивается».

Машины подключает и видит только владелец сервера: в панели они в блоке «Машины для посылок» вкладки «Ресурсы».

Что остаётся на сервере и что видит машина

ГдеЧто
Только на сервереБаза данных, участники и их ключи входа, скрытые ответы (solution.csv), код метрики, счёт и лидерборды, очередь и её порядок. Метрику каждой посылки сервер считает сам, во втором одноразовом контейнере, — и тогда, когда тетрадь исполнила машина.
МашинеТетради посылок, которые она исполняет; открытые данные соревнования; готовые наборы «своих пакетов» его участников — по ним видно, какие пакеты выбрали соперники. Образ среды машина скачивает из реестра сама, по дайджесту, который назвал сервер.
Только доверенной машинеСкрытый тест — входные данные, которые тетрадь читает при проверке вместо открытого примера (см. скрытый тест). По умолчанию машина не доверенная.
НикогдаСкрытые ответы, код метрики, счёт, имена участников, их почта и ключи входа, база данных, токен relay.

Обратно машина присылает файл ответа submission.csv, исполненную тетрадь и отчёт о прогоне. Сервер принимает их как данные участника: проверяет размеры и суммы, раскладывает файлы сам, а тексты для участника — в том числе короткие, при скрытом тесте, — пишет своими словами. Границы подробнее — в разделе «Изоляция и ограничения».

Метрика соревнования с видеокартой считается на сервере в лёгком образе kaggle-base (numpy, pandas, scikit-learn, scipy), а не в GPU-образе соревнования на 10–13 ГБ: метрике нужны две таблицы, а не карта. Образ закрепляется за соревнованием при первой его оценке и дальше не меняется — ни для новых посылок, ни при пересчёте: перевести метрику на текущий kaggle-base можно только явно, и тогда пересчитываются все посылки соревнования. Поэтому держите kaggle-base готовым на сервере до первой оценки (KERNEL_PRELOAD=base,kaggle-base): соревнование, первая метрика которого посчиталась без него, остаётся на закреплённых образах самих посылок, как до этой версии. Метрика, которая импортирует torch, здесь упадёт как код метрики — «УПАЛА МЕТРИКА», и после правки её можно пересчитать. Метрика соревнования без карты по-прежнему считается в закреплённом образе посылки.

Подключите машину

  1. В панели откройте вкладку «Ресурсы» и в блоке «Машины для посылок» нажмите «Подключить машину».
  2. Задайте, сколько машин подключится по одному коду, сколько часов код действует (до 24), места на машину (пусто — по ядрам, см. места) и, если нужно, «Доверить машинам скрытый тест» — по умолчанию выключено.
  3. Нажмите «Показать команды». Код покажется один раз — внутри трёх готовых команд. Выполните одну из них: первые две — на самой машине, от root; третью — у себя, из checkout репозитория.
# Docker уже стоит: Linux amd64, Docker Engine 28+; машине с GPU нужен ещё nvidia-container-toolkit
docker run -d --name colloq-runner --restart unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /var/lib/colloq-runner:/var/lib/colloq-runner \
  -e COLLOQ_RUNNER_JOIN='https://colloq.example.edu#<код>' \
  ghcr.io/colloq-edu/colloq-server:X.Y.Z runner

# Голая машина (Ubuntu): ставит Docker и colloq-host, а тот — NVIDIA Container Toolkit
command -v docker || curl -fsSL https://get.docker.com | sh
docker run --rm -v /usr/local/sbin:/host ghcr.io/colloq-edu/colloq-server:X.Y.Z install-host /host
colloq-host runner up https://colloq.example.edu <код>

# VM на Vast, из checkout репозитория (см. ниже)
make vast-runner COUNT=3 CODE=<код> URL=https://colloq.example.edu

Код — 32 шестнадцатеричных знака. В первой команде он стоит в адресе после #: эта часть адреса не уходит в строку запроса. Код действует для заданного числа машин и не дольше суток. Сервер хранит только его отпечаток, поэтому показать код второй раз нельзя — выпустите новый. Отправляйте его тому, кто ставит машину, а не в общий чат: пока код действует, по нему подключится любая машина, и она увидит тетради участников.

Под командами окно пишет «Ждём первую машину…», а потом называет подключившиеся. Окно можно закрыть: машины появятся в списке сами. Подключённая машина сразу начинает скачивать образы сред и данные открытых соревнований, а посылки соревнования берёт, когда для него всё готово (см. готовность). С одного адреса сервер принимает не больше 10 подключений за 10 минут: машины за одним NAT подключайте партиями.

Без панели. Если до панели не добраться — например, на сервер ходят только по SSH через Teleport, — тот же код выпускает на машине сервера colloq-host runner-code. Он печатает код один раз, внутри тех же трёх команд:

colloq-host runner-code --machines 3 --hours 12
colloq-host runner-code --machines 2 --trusted --slots 4 --prefix lab

--machines — сколько машин подключится по коду, от 1 до 100 (по умолчанию 1); --hours — сколько часов код действует, от 1 до 24 (24); --trusted — машины сразу получат скрытый тест; --slots — не больше стольких мест на каждой машине, от 1 до 64; --prefix — имена машин на сервере (lab-1, lab-2…; без него машину называет её имя хоста, а переименовать её можно на её странице); --url — адрес, по которому машины придут к серверу (по умолчанию PUBLIC_URL).

Какой образ в командах. Тот, на котором работает сервер: опубликованный выпуск — как ghcr.io/colloq-edu/colloq-server:<версия>, образ из вашего реестра или зеркала — целиком. Во втором случае команды make vast-runner нет: арендованные машины берут опубликованный образ, а не ваш. Для закрытого реестра передайте colloq-host runner up переменные COLLOQ_REGISTRY_USER и COLLOQ_REGISTRY_TOKEN (токен только на чтение): Docker машины войдёт в реестр образа, и агент с тем же входом скачает ядра из того же реестра.

Что нужно машине

  • Linux на x86-64 и Docker Engine 28 или новее. Образ собирается только для amd64.
  • Выделенная машина. Агент держит Docker socket, а это root на машине. Он отдаёт посылкам все карты, какие найдёт, и считает свободную память по всей машине, ничего не зная о комнатах занятий на том же Docker. Поэтому не ставьте его рядом с сервером, на котором идут занятия: colloq-host runner up предупреждает, если находит там контейнер сервера. Вуз одалживает соревнованию машину, которую может отдать целиком.
  • Диск: не меньше 40 ГБ без карт и 120 ГБ с картами. Ядро для процессора занимает около гигабайта, GPU-ядра — около 10–13 ГБ, сверху — кэш данных и пакетов и сами прогоны. Меньший диск машина показывает в панели как «на диске мало места»; когда место кончается, она сама удаляет то, что давно не нужно.
  • Для видеокарт — драйвер NVIDIA 580 или новее и NVIDIA Container Toolkit. GPU-ядра собраны под CUDA 13.0, и на старом драйвере torch карты не видит. colloq-host runner up ставит toolkit сам, через apt, но не драйвер, и сразу говорит, годится ли драйвер. GPU-образ машина проверяет коротким запуском torch на карте и не берёт GPU-посылок, пока проверка не прошла: в панели это «драйвер 535, нужен 580+ — GPU-образ не запустится». Посылки на процессоре она при этом берёт.
  • Только исходящие соединения. HTTPS к адресу сервера (PUBLIC_URL; http:// — только для сервера в той же сети), к реестру образов (ghcr.io или ваш) и к индексу пакетов, откуда сервер брал «свои пакеты» участников; если индекс недоступен, машина берёт пакеты у сервера. Входящих портов не нужно. Исходящий прокси и внутренний CA (HTTPS_PROXY, NO_PROXY, NODE_EXTRA_CA_CERTS) передайте вызову colloq-host runner up: он запишет их в /etc/colloq/runner.env. Образы скачивает сам Docker машины, и прокси ему задают отдельно, как на сервере (см. исходящий прокси).
  • Каталог агента — /var/lib/colloq-runner, на хосте и в контейнере по одному пути; в нём удостоверение машины (права 0700) и кэш. Другой каталог задаёт COLLOQ_RUNNER_STATE — только отдельный, например /srv/colloq-runner: системные каталоги и каталог состояния сервера Colloq агент не примет.

Серверу машины добавляют одно требование: он держит образ среды каждого соревнования, посылки которого считают машины, — по этому образу он принимает и закрепляет посылки, а машины скачивают тот же образ из реестра. Для GPU-соревнования это GPU-ядро, около 10–13 ГБ на диске сервера, даже если сам он тетрадей не считает, и ещё kaggle-base для метрики.

Места, карты и доверие

Места — сколько посылок машина считает одновременно. По умолчанию — авто: столько, сколько машина сама предлагает по своим ядрам и памяти. Себе и Docker она оставляет одно ядро и 2 ГБ памяти, а посылку берёт, только если пределы соревнования — ядра и память, и ещё 256 МБ сверху — помещаются в то, что осталось. Своё число, от 1 до 64, задают в окне подключения («Места» → «на машину»), пунктом «Места…» в меню строки или на странице машины; пусто — снова авто. Свободное место машины сервер занимает в том же честном порядке очереди, что и свои места.

Карты. Машина отдаёт посылкам все свои карты — в отличие от сервера, где карты для посылок отмечает владелец. Сколько посылок делят одну карту, задаёт пункт «Посылок на карту…» в меню машины; пусто — как на сервере, в блоке «Видеокарты для посылок» («Посылок на одной карте»). Срез видеопамяти — память карты, делённая на это число, и держат его так же, как на сервере: ограничением PyTorch изнутри и сторожем снаружи (см. видеокарту для посылок). Машина без карт GPU-посылок не берёт.

Доверенная машина — единственная, что получает скрытый тест. Доверие дают при подключении («Доверить машинам скрытый тест») или потом — пунктом «Доверенная» в меню строки или на странице машины. Снятое доверие возвращает в очередь её прогоны со скрытым тестом и удаляет скрытый тест с машины. Пока доверенной машины нет, посылки со скрытым тестом считает сервер, если тетради на нём включены, а иначе они ждут: «ждёт доверенную машину: скрытый тест». Арендованной машине скрытый тест лучше не доверять: всё, что на ней лежит, видит хозяин хоста.

Готовность. Для каждого соревнования, которое открыто, откроется в ближайшие сутки или где ждут посылки, машина заранее скачивает образ среды, данные и, если она доверенная, скрытый тест, сверяя суммы. Посылки соревнования она берёт, только когда всё на месте; пакеты участников качает тоже заранее, а недостающие докачивает при подготовке посылки — время скачивания не входит во время тетради. В строке это выглядит как «образ ↓ 45 %», «данные ✓», «скрытый тест — только доверенным». «Считает только сервер» стоит у соревнования, среда которого собрана на этом сервере: её образа нет в реестре, и машины её не получат (см. среды из реестра). Подготовка, которая не удалась, называет причину: «драйвер 535, нужен 580+ — GPU-образ не запустится», «torch не видит CUDA — GPU-образ не запустится», «образ не скачался», «данные не скачались или не сошлись суммы», «на диске мало места».

Страница машины (пункт «Страница машины» в меню): что машина сообщила о себе — ядра, память, диск, карты, драйвер, Docker; её места, посылки на карту и доверие; готовность к каждому соревнованию; что она считает сейчас, с кнопкой «Остановить посылку»; последние 50 событий и счётчики — сколько посылок она посчитала, сколько было потерь и отказов.

Пульт соревнования группирует исполнителей: «Сервер» и каждая машина со своими местами и картами; у идущей посылки видно, на какой машине и карте она считается. У ждущей посылки стоит причина, если та ждёт не просто своей очереди: «машины качают образ», «машины качают данные», «ждёт доверенную машину: скрытый тест», «ждёт карту: её нет ни здесь, ни на машинах», «некому считать: сервер считает только метрики, а машины работу не берут», «вернулась: vast-1 замолчала». Посылка, тетрадь которой посчитана и ждёт метрики, — «оценивается».

«Работают сейчас» во вкладке «Ресурсы» показывает соревнование, тетради которого идут на машинах, отдельной строкой — с машинами под ней и памятью «0 МБ здесь»: посылки на машинах памяти сервера не занимают, здесь остаются только их строки в очереди и метрика пришедших ответов.

Редактор соревнования в строке «Где считается» говорит, кто возьмёт его посылки: сервер, сколько машин и мест, какие машины ещё готовятся и какие не подходят. Он же предупреждает, если среду собрали на этом сервере («только этот сервер») или если посылки со скрытым тестом некому считать.

Тетради на этом сервере и оценки

Над списком машин — два поля формы «Ресурсы»; сохраняет их кнопка формы «Сохранить изменения».

  • «Тетради на этом сервере». «Считать и здесь» (по умолчанию) — тетради считают и сервер, и машины. «Только метрики» — тетради считают только машины, сервер оценивает пришедшие ответы, а его ядра остаются занятию. Если при «только метрики» на связи нет ни одной машины, посылки ждут, и блок так и пишет. Посылки среды, собранной на этом сервере, и посылки со скрытым тестом без доверенной машины при «только метрики» считать некому — редактор соревнования предупреждает об этом.
  • «Оценок одновременно» — сколько метрик сервер считает одновременно: от 1 до 8, по умолчанию 2. Метрика — до 2 минут и 2 ГБ на ответ. Метрики ответов с машин и пересчёты идут по этим местам, а не по местам тетрадей.

Обновление

Машина берёт новые посылки, только пока её код совпадает с кодом сервера — сборкой агента из того же выпуска. Выпуск, который не трогает код машин, оставляет их в работе как есть. Выпуск, который его меняет, переводит их в состояние «устарела»: начатые посылки они досчитывают, новых не берут, а в строке написано, например, «код 0.23.0, сервер 0.24.0 — новых посылок не берёт». Поэтому порядок такой: сначала сервер, потом машины.

# 1. Сервер, как обычно
colloq-host update ghcr.io/colloq-edu/colloq-server:X.Y.Z

# 2. Машины на Vast — все машины этого сервера, из checkout репозитория
make runners-update URL=https://colloq.example.edu

#    или любая машина, по SSH, от root
colloq-host runner update

colloq-host runner update узнаёт версию сервера по его /api/health, скачивает её образ, осушает машину — начатые посылки досчитываются, новых она не берёт — и запускает агента на новом образе; заодно обновляется и сам colloq-host. Осушение ждёт не дольше самого длинного прогона, какой допускает протокол (COLLOQ_RUNNER_DRAIN_SEC, по умолчанию 15 720 с). С --now оно не ждёт: начатые посылки возвращаются в очередь и считаются заново — без потерь и без траты попыток участников. Версию можно назвать и явно: colloq-host runner update 0.24.0.

make runners-update делает то же на всех машинах Vast сразу. На каждой машине обновление идёт в фоне и переживает обрыв SSH, а повторный вызов подхватывает уже идущее. Машину, чей код уже совпадает с сервером, команда не трогает (FORCE=1 — обновить всё равно); NOW=1 — то же, что --now; VERSION= — одна версия для всех.

Перезапуск сервера посылки на машинах не обрывает: машины досчитывают их и отправляют результаты, когда сервер снова на связи, а первые 3 минуты после старта сервер ни одну машину не считает пропавшей. Обновляйтесь всё же между соревнованиями, а если не вышло — обновите машины сразу после сервера. Сами себя машины в этой версии не обновляют.

Отключение и уход

  • colloq-host runner leave на машине: она досчитывает начатое, новых посылок не берёт, отзывает себя на сервере и удаляет контейнер агента. Кэш образов и данных остаётся в /var/lib/colloq-runner — удалите каталог, чтобы освободить диск. Вернуть машину можно только новым кодом: со старым она не подключится, даже если on-start Vast повторит его при загрузке.
  • make runners-down URL=https://colloq.example.edu — то же для машин Vast этого сервера, после чего их VM удаляются вместе с дисками; сначала команда спрашивает подтверждения. С NOW=1 VM удаляются сразу, без ожидания: сервер потеряет машину через 3 минуты молчания и посчитает её посылки заново, а в списке она останется, пока её не отключат.
  • «Отключить» в меню строки (или «Отключить все» под списком): сервер сразу перестаёт принимать секрет машины. Её посылки возвращаются в очередь без потери лимита, поздние ответы не принимаются, а агент на следующем запросе удаляет скрытый тест и останавливается, чтобы больше не запускаться. Арендованную VM это не удаляет, и она тарифицируется, пока её не удалят. Подключить машину снова можно только новым кодом.

Участникам уход машины ничего не стоит: посылки, которые она не досчитала, считаются заново на другом месте, а сам уход не тратит ни дневной нормы, ни попыток.

Если машина подводит

  • Молчит. Машина, которую сервер не слышит 3 минуты, теряет свои прогоны: они возвращаются в очередь на своё место — раньше тех, кто пришёл после них, — и запускаются снова, на другой машине или на сервере. Участник читает: «Машина, на которой шла посылка, перестала её выполнять. Посылка вернулась на своё место в очереди и запустится снова; попытка не потрачена». Пропавшей машину сервер считает, только если знает, что дорога к машинам работает: другая машина отвечала в последнюю минуту или прошла его собственная проверка своего адреса. Если пропала сама дорога — упал туннель или прокси сервера, — ничего не теряется до 15 минут.
  • Отказывается. Машина, которая не может запустить посылку — нет образа, данных или пакетов, не хватает диска, памяти или доли карты, — возвращает её до старта контейнера. Посылка сразу уходит на другое место, а эта машина не получит её 10 минут. Участнику отказ ничего не стоит.
  • Теряет снова и снова. Посылку, которую потеряли три разные машины или шесть раз — любые, сервер больше в очередь не ставит: она заканчивается сбоем сервера — «Это сбой сервера, а не вашей тетради; попытка не потрачена» — и не тратит ни нормы, ни потолка упавших; исполнить её заново можно из пульта. Так же заканчивается посылка, от которой отказались три разные машины.
  • Зависает. Прогон, который тянется дольше своего предела — 10 минут на подготовку, время тетради, ещё 2 минуты и 10 минут на отправку результата, — сервер отзывает и считает потерянным, даже если машина продолжает отвечать.
  • Карантин. Три потери или пять отказов на одной машине за 30 минут — и сервер сам её осушает: она досчитывает начатое и больше ничего не берёт, а над списком появляется баннер. Посмотрите события на странице машины и, устранив причину, нажмите «Вернуть в работу».
  • Перезапуск агента. Если контейнер агента перезапустили или машина перезагрузилась, начатые на ней прогоны сервер сразу считает потерянными и ставит в очередь заново. Остановленный агент (docker stop, colloq-host runner update --now) сначала возвращает их серверу, без потерь.

Машины на Vast

Из checkout репозитория, с VAST_TOKEN и SSH-ключом в .env, как для make vast-vm:

make vast-runner COUNT=3 CODE=<код> URL=https://colloq.example.edu
make vast-runner COUNT=2 GPU="RTX 4090" GPUS=2 DISK=150 CODE=<код> URL=https://colloq.example.edu

Команда арендует COUNT VM, от 1 до 16, тем же путём, что make vast-vm: с теми же фильтрами предложений (GPU=, GPUS=, GPU_RAM=, CPU=, RAM=, DISK=, MAX_PRICE=) и тем же порогом Max CUDA 13.0. Сначала она пишет, что и почём арендует, и спрашивает подтверждения (FORCE=1 — без вопроса). Машины арендуются по очереди — каждая берёт самое дешёвое подходящее предложение — и загружаются одновременно; каждая ждёт, пока её агент подключится. Код должен быть рассчитан хотя бы на COUNT машин; URL= можно один раз записать в .env как VAST_RUNNER_URL.

Диск по умолчанию — 120 ГБ: VM без карт на Vast не бывает, а машине с картами нужны GPU-ядра. Машина для посылок на процессоре — это VM подешевле с нужным числом ядер (CPU=), и её карта тоже возьмёт GPU-посылки.

В on-start арендованной VM — только адрес сервера и код: ни токена relay, ни других ключей. On-start видит оператор хоста, и Vast хранит его в консоли, а код через сутки или после COUNT подключений ничего не стоит. Версию образа машина узнаёт у сервера, поэтому после обновления сервера новый on-start не нужен — нужен make runners-update.

Машины помечаются на Vast меткой colloq-runner (с NAME= — colloq-runner-<NAME>), и по ней их находят make runners-update и make runners-down. Каждую машину они сначала спрашивают по SSH, какому серверу она служит; с URL= берутся только машины этого сервера, без него — все машины аккаунта с этой меткой.

Оплата — ваша. Машины тарифицируются на вашем аккаунте Vast, пока их не удалят. В том числе те, что арендовались, но не подключились (сервер не ответил, у кода кончились подключения): их нет ни в одном списке машин. Команда в конце называет каждую такую машину и печатает команду её удаления, а с DESTROY_UNJOINED=1 удаляет их сама. Машина, отключённая в панели, тоже тарифицируется, пока её не удалят — make runners-down или в консоли Vast.

Среды из реестра и GPU-ядра

Образ среды машина скачивает не у сервера, а из реестра — по дайджесту, который сервер записал, когда сам получил этот образ, — и перед запуском сверяет его слои с образом сервера. Поэтому машины считают только те среды, образ которых сервер скачал из реестра. base и kaggle-base публикуются с каждым выпуском; GPU-ядра base-gpu и kaggle-gpu — отдельной командой make kernel-publish на машине с картой, при выпуске (RELEASING.md). Сервер берёт их из реестра, если они перечислены в KERNEL_PRELOAD, например KERNEL_PRELOAD=base,kaggle-base,base-gpu,kaggle-gpu.

Среду, собранную или изменённую на этом сервере, в этой версии считает только сервер: её образа нет в реестре. В списке машин такое соревнование помечено «считает только сервер», в редакторе — «только этот сервер». С KERNEL_IMAGE_REPO=none сервер собирает все среды сам, и машинам считать нечего. Так же остаётся на сервере GPU-ядро, которое он собрал сам, пока ядро его версии ещё не было опубликовано; как перейти на опубликованное — в том же разделе RELEASING.md.

Чего машины пока не делают

  • Не готовят «свои пакеты» участников: наборы готовит сервер (на Docker-пути ему нужен Docker Engine 28 или новее), машины только скачивают готовые.
  • Не запускают ядра комнат: занятия идут на сервере, как и раньше.
  • Не обновляются сами: после обновления сервера нужен make runners-update или colloq-host runner update.
  • Не подписывают запросы. Машина предъявляет свой секрет в заголовке, а TLS заканчивается на обратном прокси или relay перед сервером: кто управляет ими, может прочитать секреты машин (см. изоляцию).
  • Не продолжают прогон после перезапуска агента: такой прогон считается заново.
  • Одна машина служит одному серверу. Арендовать машины из панели нельзя — только make vast-runner или руками.
  • Сервер в Kubernetes (Helm-чарт) машин для посылок в этой версии не подключает.
  • Нагрузочной репетиции с машинами ещё не было: сколько посылок в минуту даёт парк машин и что это значит для занятия на сервере, мы пока не измеряли.
