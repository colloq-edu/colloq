Обновление и откат

Обновляйте в окно обслуживания и сохраняйте совместимый путь назад.

До обновления

  1. Получите выбранный выпуск и соответствующие ему инструменты; проверьте суммы и манифест.
  2. Убедитесь, что образы доступны с используемыми registry-правами, а на диске хватает места для backup.
  3. Проверьте заявленную совместимость схемы данных и сохраните внешний backup текущего состояния.
  4. Согласуйте перерыв: приложение, брокер и ядра будут заменены.

Используйте инструменты выбранного выпуска. Установка не подменяет отсутствующий digest и не принимает локально исправленный архив инструментов.

Выполните обновление

sudo scripts/cluster.sh update --release next-release.json
sudo scripts/cluster.sh status
sudo scripts/cluster.sh smoke

Preflight проверяет реальную загрузку образов и non-root execution до остановки писателей. Update проверяет совместимость и делает согласованную переносимую копию, затем останавливает приложение и runtime-нагрузки. Тетради и файлы остаются; переменные Python теряются.

После обновления проверьте старую комнату, новую комнату, публикации, файлы и исполнение. Убедитесь, что старые занятия продолжают использовать закреплённые ревизии окружений.

Когда нужен откат

sudo scripts/cluster.sh rollback --release previous-release.json
sudo scripts/cluster.sh status
sudo scripts/cluster.sh smoke

Rollback также проверяет совместимость, создаёт consistent-backup и требует перерыва. Возврат старого образа не отменяет несовместимую миграцию базы: в таком случае нужен подходящий backup и процедура восстановления.

При неудачной readiness-проверке желаемый выпуск остаётся записанным, а предыдущий находится в releases/previous.json. Оператор выбирает откат явно; автоматического непроверенного понижения схемы нет.

Версия k3s меняется отдельно

Colloq-выпуск требует точную версию k3s. Её изменение — самостоятельная операция: backup datastore и server token, план обновления k3s, затем Colloq-выпуск, совместимый с новой точной версией. Обычный update приложения не обещает безопасного upgrade кластера.

Старые комнаты и образы

Сохраняйте registry-образы, на которые ссылаются старые комнаты и резервные копии. Даже если окружение исчезло из нового выпуска, каталог сохраняет нужные прежние ревизии. Очистка registry должна учитывать эти ссылки.

Одна VM и локальные тома предполагают обслуживание с перерывом. Этот процесс не обеспечивает HA или обновление без остановки.
